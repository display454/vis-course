# 01 · 目标页面现状审计（UI Audit）

> 对象：《可视化导论》课程网站（`vis-site/`），两类核心页面——**首页 `index.html`**（Landing + 章节入口 + 知识地图）与**章节模板 `chapter.html`**（讲解 / 关键代码 / 演示三视图，含 27 个 D3 演示）。
> 审计方式：真实浏览器（Chromium，CDP 精确视口）观察；视口覆盖 **390 / 768 / 1024 / 1440 / 1920**，桌面与移动端、中英双语。证据截图见 `_shots/audit/`（`before-*` / `true-*`）。
> 重要说明：新无头 Chromium 的「桌面窗口」存在约 490px 的最小宽度，直接用 `--window-size=390` 会把布局视口钳到 490 而画布仍为 390，造成"右侧被裁切"的**截图假象**。审计已改用 CDP `Emulation.setDeviceMetricsOverride`（mobile=true）得到真实 390px 布局，结论以真实视口为准。

## 一、页面定位与"什么是好设计"

- **页面类型**：面向大学生的**交互式教学/课程文档站**（不是营销站，也不是纯文档）。它同时承载：①课程门面（首页）；②连续阅读的讲义；③可运行的代码；④27 个可交互实验。
- **核心任务**：让学生在"原理 → 代码 → 效果"之间快速来回对照；课堂投影时后排可读；课后手机上可复习。
- **用户**：中国石油大学（华东）本科学生（AI/编程方向）、授课教师。
- **优秀标准**：**清晰的信息层级 + 可预期的阅读路径 + 图表/控件本身成为教材 + 桌面与移动端均可用 + 零构建可托管**。参照对象应是 Observable/Distill/Nicky Case 的"可探索解释"、Stripe/GitHub/VitePress 的"文档阅读布局"、Datawrapper/OWID 的"图表克制"，而非营销 Landing。

## 五、审计结论

- **不是推倒重做**：令牌、字体、三视图、演示外壳已成熟，本次为"比例、布局、状态、移动端"的精修与统一。
- **收益最大的三块**：①移动端表格/宽图/Tab/触控（P0，1–4）；②首页纵向节奏与知识地图/bento 比例（P1，5–8）；③阅读列与图表列宽度体系（P2-13）。
- **风险**：仅改 CSS/少量 JS（宽图滚动、Tab 文案），不动内容与交互逻辑；所有改动都要可回溯到调研案例与规格（见 02–04）。
